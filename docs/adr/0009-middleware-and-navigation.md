# ADR 0009 — Middleware, navigation, and where the WASM actually loads

Status: accepted
Date: 2026-08-23

## Context

This is where the design meets Next.js. Everything before it was testable in
isolation; the middleware, the navigation wrappers and the WebAssembly loading
only tell the truth against a running application. Building
`examples/next-16-proxy` was not documentation work — it is what surfaced four
of the five decisions below, none of which any unit test had a chance of
catching.

## Decisions

### The Edge and Node binaries are embedded, not loaded from disk

This is the important one, and it was found the hard way.

- **Node.** wasm-pack's `nodejs` glue locates its own `.wasm` through
  `__dirname`. Webpack rewrites that to a chunk directory; Turbopack rewrites it
  to a literal `W:\ROOT\…` placeholder. Neither copies the binary there, so the
  build reports success and the first request fails with `ENOENT`.
- **Edge.** The `bundler` glue resolves its `.wasm` through a relative URL, and
  the Edge runtime has no base to resolve one against. The middleware throws
  `Failed to parse URL from /_next/static/wasm/….wasm` on the first request.

Next's documented answer for the Node half is `serverExternalPackages`. It was
tried, and it does work — but only for a real install (a workspace symlink
resolves outside `node_modules`, so Next skips it), and externalising the whole
package takes the `'use client'` entries with it, which breaks the client
boundary. A cure worse than the disease.

Both builds therefore use the `web`-target glue and are handed their bytes
directly, as base64 generated by `scripts/sync-wasm.mjs`. No path is resolved at
runtime, under any bundler, in any deployment layout — and an application needs
no configuration at all.

The browser is deliberately excluded: there the bytes are paid for over the
network, where a real `.wasm` module is smaller than base64 and streamable.

The cost is the Edge middleware bundle going from 38.5 KB to 116 KB. That is not
downloaded by a browser, and it buys the removal of an entire class of
production-only failure.

### The matcher cannot be shared

Next reads `config.matcher` by static analysis at build time and rejects an
imported identifier — `Unknown identifier "DEFAULT_MATCHER"`. The constant is
still exported as `RECOMMENDED_MATCHER` for documentation and tests, but the
pattern has to be written out in each application's `middleware.ts`.

This is worth knowing about because getting it wrong is silent. A single
backslash — `'\.'`, which JavaScript reads as plain `.` — turns the
file-extension exclusion into "any character", and the middleware then stops
running on every path except `/` with no error anywhere. The core's own
`should_handle` is the second guard against exactly that class of mistake.

### Navigation re-exports the client entry rather than the source

`i18n-fs/navigation` and `i18n-fs/client` are separate bundle entries and the
build does not split shared code, so importing `./client/context.js` from both
gave each its own `createContext` call — two contexts. A `<Link>` then read a
context the provider had never populated, which surfaces as
"No I18nProvider found" on a page that plainly has one.

`i18n-fs/navigation` is now a re-export of `i18n-fs/client`. Same reasoning as
the provider in [ADR 0007]; the rule is that any module holding state belongs to
exactly one entry.

### The navigation helpers duplicate two small functions from Rust

`<Link>` cannot be asynchronous, and reading the WASM core would make every link
suspend on first paint. So `src/paths.ts` mirrors `add_locale` and
`strip_locale` in TypeScript — and only those two, because building a link means
adding a prefix to a path that never had one, none of the fixed-point reasoning
the middleware depends on.

A mirror that drifts is worse than no mirror: links would point where the
middleware then redirects away from. `test/paths.test.ts` therefore checks the
copy against the original over the full cross-product of strategies, prefix
modes, default locales, hosts and adversarial paths — 3,564 comparisons — rather
than against hand-written expectations.

### A locale switch is a full page load

`useLocaleSwitcher().switchTo()` sets the cookie and calls
`window.location.assign`. Every layout and Server Component above the switcher
was rendered in the old locale, and only a fresh request re-runs them; a soft
navigation would leave half the page in the previous language.

The cookie is written by the switcher as well as by the middleware, so the
choice survives even where the URL cannot express it.

### A client namespace missing during SSR says what to do

A Client Component reading a namespace the provider did not send tries to fetch
a relative URL, which has no origin while it is being server-rendered. Rather
than let that fail as `Failed to parse URL`, the loader detects the server and
returns a diagnostic naming the fix: add the namespace to `<I18nProvider>`.

## Testing

The end-to-end suite runs at the **HTTP level** against a real `next start`,
not through a browser. The property under test is that a redirect chain
terminates and settles on the locale it was asked for, and that is a statement
about status codes and `Location` headers. A browser would add a large download
and considerable machinery while observing nothing more — and its automatic
redirect following would *hide* the chain, which is the very thing being
measured.

Browser-level coverage is still worth having for the switcher and hydration, and
is a reasonable addition later. It is not what proves the loop guarantee.

## Consequences

- Applications need no `next.config` changes. `withI18nFs` remains for the
  webpack WebAssembly flag, which is now only relevant if someone imports the
  browser build in an unusual way.
- The example app is part of the test suite, not a sample. It is the only place
  the real matcher, the real Edge runtime and the real binary meet.
- Two implementations of prefix handling now exist. The Rust one is
  authoritative; the TypeScript one is guarded by an equivalence test that must
  keep passing.
