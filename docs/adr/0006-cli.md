# ADR 0006 — The CLI ships inside `i18n-fs`, and is mostly JavaScript

Status: accepted
Date: 2026-08-22

## Context

`i18n-fs` never falls back to another locale's content ([ADR 0003](0003-fallback-policy.md)).
That is the right behaviour, but it means a key missing from one locale is
invisible until a reader of that locale opens the page. Something has to turn
that into a build failure, and something has to produce the artefacts the
runtimes cannot derive for themselves.

## Decisions

### One package, not two

The CLI is a `bin` inside `i18n-fs` rather than a separate `i18n-fs-cli`
package. Installing one thing is better than two, and the CLI code lives in its
own entry point, so it never reaches an application bundle.

### Node, calling into the existing Rust core

The heavy lifting that belongs in Rust is already there: parsing a namespace,
indexing its keys, and reporting exactly why a file is unusable. The CLI calls
that through the Node WASM build.

The rest — walking directories, hashing files, comparing two sets of keys,
templating a `.d.ts` — is I/O and set arithmetic. Node does it natively and
faster than a WASM boundary crossing would, and ADR 0001's rule applies: every
function has to justify its place in Rust, and these do not.

### Introspection is a fourth cargo feature, not part of `full`

Enumerating a namespace (`entries`, `scopes`) is a build-time concern. Adding it
to the `full` feature pushed the browser binary from 89.6 KB to 93.3 KB gzip and
the size budget caught it in the same run it was written.

It now sits behind a `cli` feature, compiled into the Node build only. The
browser resolves messages; it never lists them. The Node build carries the extra
3.6 KB because it is read from disk rather than downloaded, and its budget is
set accordingly.

### No new dependencies

The config is imported directly. Node strips TypeScript types natively from
22.18 onward, so `i18n-fs.config.ts` loads with no bundler — which is why the
package now requires that version. Pulling in esbuild to read one config file
would make everyone who installs the runtime pay for a build-time concern.

### Types come from the default locale alone

The default locale is the single source of truth for what keys exist; `check` is
what guarantees the others match it. Generating from the union of all locales
would type keys that are missing exactly where they are used.

That reasoning is conditional, which only became visible when the condition was
made optional. `compareLocales: false` withdraws the guarantee, and the registry
has to stop relying on it: there the union *is* what is true, and it is the only
version that compiles for a project whose locales legitimately differ. The
setting therefore decides both what `check` reports and what `build` generates —
one value, or the two would disagree about which locales count.

Keys inside a list are deliberately excluded from the generated types. A list of
ten strings is also ten indexed keys and one scope, and typing them would bury
the real keys in numeric noise. They stay resolvable at runtime — `t.array(key)`
is how a list is meant to be read.

### `build` refuses to write when `check` fails

A manifest and a type registry generated from a broken message tree would
describe something that does not exist. The commands share one analysis pass so
they cannot disagree.

## Diagnostics

Findings carry a stable code so `--json` consumers and CI can act on them, and
each problem is reported once at its shallowest point:

- A file that fails to parse reports `INVALID_JSON` with the parser's line and
  column, and is then excluded from the key comparison — it does not also
  produce `NAMESPACE_MISSING` and one `KEYS_MISSING` entry per key it contains.
- A locale missing an entire list reports the list, not the list plus every
  index inside it.
- Shapes are compared, not just names. A key that is a string in one locale and
  a list in another passes a name-only comparison and then breaks `t.array` for
  the readers of one language only.

## Consequences

- `.i18n-fs/` output is deterministic: sorted keys, stable formatting, and the
  same bytes on a repeat run. It can be committed or ignored without producing
  noise either way.
- The generated `MessageRegistry` is the contract PR #4's `useTranslation`
  consumes. Changing its shape means changing both together.
- `check` is what makes "no cross-language fallback" survivable in practice. It
  belongs in CI.
